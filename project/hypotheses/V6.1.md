# VisionJev v6.1

## A grounded plan: fix the three measured failures, pick a production backbone, ship a 4B tier

**Status:** revision of V6.md after the 2026-09-28/29 results (30B v5 pod run, JevBench public on 500M / 2B / 30B, truncation
finding, overfitting check, serving-cost measurement, Imajev review). Every number below is from `results/experiments.jsonl`
or a cited source; every estimate is marked as one.

**What changed from V6:** V6 was a research vision that did not know what already exists in `laya-vision/`, did not know
that a third of the 30B's hard-tier gap was an input-budget bug, never chose a backbone, and had no budget or order.
V6.1 keeps V6's principles (protect the base, treat abstention as selective prediction, verify reasoning with code, test
before believing) and turns them into a sequenced plan with acceptance criteria.

## 0. The three failures we are fixing, with their evidence

|---|---|---|---|
| F1 | **Hard multi-step reasoning** | JevBench hard: 2B 41%, 30B 53% at its trained 1,346-token budget, 64% at 4,096; Imajev-4B 72%. ## 1. Goals and non-goals

**Goals (measurable, in order):**
1. JevBench public: 4B-class product model ≥ 82% (hard ≥ 65%), ECE ≤ 0.04; 30B teacher tier ≥ 86% (hard ≥ 72%).
2. Option-order flip rate < 1.5% (from 5.8–7.1%) without inference-time rotations.
3. Never-seen (`novel_text`) ≥ 80% on the product model (30B today 71.3%, 2B 50.6%).
4. Product model ≤ 25 ms / text decision, ≤ 120 ms / image decision on one H100-class GPU; ≤ $0.03 / 1k decisions.
5. Keep what we are already good at: zero-shot image panels, execution-verified code, robotics (no regression > 2 points).

**Non-goals for v6.1:** latent iterative reasoning (Coconut-style), ensembles in production, a 5–10k human-audited
multimodal benchmark, Dirichlet / conformal calibration as shipping components. They stay as P2 research notes (§13).

### 3.2 Recommendation

**Product tier: a 4B.** Imajev's own numbers say that after the right training the 4B and the 9B are indistinguishable on
decisions (82.4 vs 82.8 ImajevBench; 72.1 vs 69.4 JevBench hard) while the 4B is 1.3× faster and half the memory. The
9B's advantage is *untuned* reasoning, which matters for a teacher, not for the model we serve.

**Which 4B: decide by a 3-day bake-off, not by belief.** Default order of preference:
1. **Qwen3-VL-4B-Instruct** if its untuned read-out is within 5 points of Qwen3.5-4B on JevBench hard at 4,096 tokens, because
   it is a drop-in and it allows the full option-attention fix (§5).
2. **Qwen3.5-4B** otherwise (Imajev-proven), accepting that order symmetry then comes from the head and the training
   objective rather than the backbone mask.

**Teacher tier: keep the 30B** (knowledge, breadth, 79.6% MMLU) and add **Qwen3.5-9B / Qwen3.6-class thinking models as
hard-question answerers** (§6.3). Do not train a 9B product model in v6.1.

### 3.3 Bake-off protocol (P0-0, ~6 GPU-hours local + one 4-hour pod)

For each of {Qwen3-VL-4B, Qwen3.5-4B, (Qwen3-VL-8B as reference)}:
1. **Untuned read-out**: score JevBench public (all 231, `--max-len 4096`), `novel_text`, `novel_vision`, and 300 rows each of
   MMLU-1000, oi_presence, doclaynet_type, code_exec_pass with (a) LM-head logits over option letters (prompted), (b) our
   randomly initialised head frozen-backbone linear probe trained 1k steps on 20k mixed rows (the "read-out penalty").
2. **Identical 2-hour fine-tune** (the diagnostic recipe: mix_v5, `--logit-cap 10`, lr 5e-5, aug on, 4,096 text budget) →
   the same evals + robustness flips + latency (bf16, batch 1, 230-token text; 1-image 589k-pixel).
3. **Selection score** = JevBench hard + novel_text + image panel mean − 10 × (flip rate) with a hard constraint ≤ 25 ms
   text (after LoRA merge) on the pod GPU. Report all numbers with bootstrap 95% CIs; n = 111 on hard means ±9 points, so
   ties within 5 points go to the drop-in.

## 4. Problem F1: hard reasoning. Methodology

Four causes, four instruments, applied in this order because each is cheaper than the next and changes how the next is run.

### 4.1 Input budget (E11) — fix before anything else

- **Training**: separate text and image budgets. Text-only rows get `max_len_text = 4096`; image rows get
  `max_len_text_with_image = 2048 + image tokens` (image tokens are accounted separately, as `default_max_len` already does for
  SmolVLM tiles). Truncate **from the middle** of the state, never the end (rules and totals live at both ends), and log the
  truncation rate per dataset; fail the data audit if any dataset truncates > 5% of rows.
- **Data**: add long-state rows on purpose (§4.3 generators emit 800–2,500-token documents; SWE issues; DUDE / DocLayNet full
  pages; multi-turn support transcripts).
- **Inference**: default `max_len` 4,096 for Qwen backbones; refuse (do not silently cut) beyond 8,192, as Imajev does.
- **Acceptance**: 30B re-eval at 4,096 already gave +5.2 points; the new checkpoint must show < 1% truncated JevBench items and
  no drop on long_policy vs the 4,096 override.

### 4.2 Diagnose reasoning loss (P0-1, E9) — one GPU-day, decides the loss function

Three measurements on the same items (JevBench hard at 4,096; `novel_text`; GSM8K-choice 500; a 300-item multi-hop table set
from the generators):

| Measurement | How | What it isolates |
|---|---|---|
| A. Base LM | untuned backbone, prompted, LM-head logits over option letters | base capability |
| B. Base + our head | frozen backbone, only `head_layers` + option head trained on 20k mixed rows | read-out penalty |
| C. Our fine-tuned model | qwen2b-mix / qwen30b-v5 | read-out + fine-tuning penalty |

Decision rule: if C < B by > 5 points on hard, fine-tuning **destroyed** capability → Phase A trains with the anchor (§4.5,
λ > 0) and we run P0-3. If B ≈ C < A, the read-out **cannot access** it → the fix is the read-out (§5) and the short delta
(§4.6), not regularisation. If A is already low (likely for the 2B), the 4B/9B bake-off numbers decide the backbone.

### 4.3 Exact-answer generators (D2) — code only, first data we add

Families, each with a seeded generator, an independent re-computation in tests, and **mistake distractors** (each wrong option
= the answer under one named error):

| Family | Kinds | Named errors that make the distractors |
|---|---|---|
| temporal_arithmetic | business-day deadlines with closures, DST / time-zone elapsed time, UTC cut-offs, overnight shifts, deemed receipt, month-end roll-over, recurring schedules, grace periods, lateness bands (score) | calendar vs business days; local read as UTC; DST hour missed; inclusive vs exclusive end; wrong month length |
| unit_conversion_rounding | lb/kg, in/cm, currency with fees, round-up-then-compare, significant figures | convert after rounding; wrong factor; round half down |
| probability_exact | draws with / without replacement, 2×2 conditionals, Bayes with frequencies, binomial exactly-k, expected cost, bands (score) | P(B\|A) for P(A\|B); with vs without replacement; forgetting complement |
| money_reconciliation | invoice totals with discount / tax / delivery, PO vs invoice, stacked discounts, proration, FX + card fee, budget with pending items | tax on undiscounted subtotal; additive discounts; proration by wrong day count |
| rule_precedence | policy with general rule + exception + override date; eligibility with 3–5 conditions; tie-break orders | apply the general rule; miss the effective date; wrong precedence |
| multi_hop_table | 2–3 small tables (customers / orders / policies) needing a join and an aggregate | join on the wrong key; aggregate before filter |
| evidence_withheld (3–5%) | any family with one required input "to be confirmed" | intended `unknown` |

Rendering: 50% plain string, 50% JSON; **25% rendered as images** (invoice / roster / policy page / chart via our
synthetic-document renderer) so the same reasoning is trained visually; question types choice / noul / score across the
same content; 15 domains with fictional entities. Target **30–50k items**, 800–2,500 tokens for the long variants, built to
`data/vqa/gen_*` with the usual validator + audit (question-only tell, longest-option tell must be ≤ chance + 0.05).
Estimated effort: 4–6 days of code, no GPU.

### 4.4 Teacher-generated hard questions (D14) — one pod, ~$40–80

Pipeline (Imajev's, with two changes):
1. **Writer**: an Apache-2.0 open-weight thinking model (Qwen3.6-27B class; verify the exact licence of the chosen revision
   allows training on outputs — Qwen3 / Qwen3.5 / Qwen3.6 are Apache-2.0). One call → one 300–1,200-word business document +
   3 typed questions from 3 different families (policy_exception, date_number_trap, multi_step_lookup, judge_pairwise,
   judge_rubric_score, ambiguity, misleading_note, injected_instruction, rule_precedence, routing, extraction, rubric,
   numerical_reconciliation, temporal_ordering, insufficient_evidence, contradiction) + intended answer + one-line reason.
   15–25% intended `unknown`.
2. **Answerers**: three, from ≥ 2 families (e.g. Qwen3.6-35B-A3B thinking, gpt-oss-20b, Qwen3.5-9B), blind to the intended
   answer, temperature 0, `unknown` offered; each returns a **distribution** over options.
3. **Pools (change 1 — no discards):**
   - unanimous with the writer → train, soft target = mean answerer distribution;
   - 2/3 agree with the writer → train with the mean distribution **only if** the writer's reason is consistent with the
     majority (cheap LLM check); otherwise eval-only;
   - all disagree with the writer → **eval-only hard set** (`teacher_hard_eval`) and a **soft-target row** with the averaged
     distribution *if* one option has ≥ 0.5 mass; never a hard label.
   - programmatic families (§4.3) never go through agreement; their label is computed.
4. **Lint**: 8-gram overlap vs JevBench public → drop; split by document; 3 held-out domains → the Jev-shaped calibration set
   (§7.1). (Change 2: the calibration set is carved here, not from our val mix.)
5. **Rationale field** kept on every row (writer's reason or the programmatic trace) for the optional rationale loss (§4.6).

Size: 6k documents → 18k questions → ~11–13k train rows (est. from Imajev's 65–70% yield) + ~3k eval-only. Cost estimate:
5–6 h on one H100 with vLLM ≈ $20–25 per answerer pass; 3 answerers + writer ≈ $60–80.

### 4.5 Phase A: broad training that does not erase reasoning

Data: mix_v5 + D13 format augmentation (§7.2) + long-state rows + generators (§4.3, 15% of draws) + per-dataset pass caps
(E5: `max_passes` 1 for sets < 2k rows; robot frames near-dup filtered harder).

Loss: `L = CE(target) + λ·anchor + β·perm_consistency`, with two anchors tested in P0-3 (the V6 "KL to base" was
undefined; these are defined):

- **R1, target blend** (Imajev's): `target' = (1−α)·label + α·p_base` where `p_base` is the **untuned backbone's LM-head
  distribution over the option labels** (letters, prompted), precomputed offline once per row (one forward per row: ~1M rows
  ≈ 6–8 GPU-hours on the 4B; rows where `max p_base < 0.35` keep the plain label because the base is guessing). α ∈ {0, 0.3, 0.5}.
- **R2, LwF on the LM head**: on a 20k-row held-out instruction/VQA corpus (never in decision training), penalise
  `KL(LM_base ‖ LM_student)` on the next-token distribution, weight λ ∈ {0.1, 0.3}. This protects general language ability
  directly; R1 protects the decision mapping.

Optimiser: AdamW, lr 5e-5 (4B) / 2e-5 (30B), cosine to 10%, clip 1.0, `--logit-cap 10`, LoRA r16–32 on **attention + MLP**
(check the expert-rank pattern on the 30B, T11), vision frozen in v6.1 (vision-tower LoRA is a P2 ablation), 1 pass over
the mix, option order re-drawn per draw, keep-best on Jev-shaped calibration NLL + hard-dev accuracy (two signals, both
logged).

### 4.6 Phase B: the short hard-reasoning delta

- Data: §4.3 generators (all) + §4.4 train pools + 15% replay of Phase A (must include images) + `laya_typed*` upsampled.
- Loss: soft CE on the target distribution; **rationale LM loss** weight 0.3 on `" Because: <reason>"` appended after the
  read-out span (causal backbones only; never produced at inference); permutation consistency β = 0.1.
- Schedule: 2 epochs, lr 2e-5 → 1e-5, expected 300–800 steps; eval every 100 steps on hard-dev (600 teacher + 400
  programmatic held-out) and the image panel; keep-best on the **mean** of the two.
- **Weight averaging**: evaluate `w·B + (1−w)·A` for w ∈ {0.5, 0.75, 1} on the gates (§10); ship the largest w that passes.
- Acceptance (4B): JevBench hard ≥ 65% at 4,096, temporal_numeric ≥ 60%, long_policy ≥ 70%, image panel within 1 point of A.

### 4.7 Phase C (optional): RLCD as calibration polish

Run only if Phase B's raw ECE on the Jev-shaped set is > 0.05. 500–1,500 steps, `--logit-cap 10`, σ annealed 0.3 → 0.05,
CE floor 0.05 (never 0), G = 8. Decision rule: keep C only if calibrated NLL improves ≥ 3% with no accuracy loss > 0.5
points; otherwise ship B and treat RLCD as retired for this product.

### 4.8 Adaptive compute: the cascade, not latent reasoning

The 4B answers; if `max p < τ_4B` (fitted on the calibration set for a target coverage), the request goes to the 30B; if the
30B's `max p < τ_30B`, it is escalated. Router features: max p, entropy, option count, image present, state length, per-task
temperature bucket (extend `visionjev_cascade.py`). Target: ≥ 85% of oracle deferral (now 78.5%). "Second pass of the same
model" is not in v6.1: with identical inputs it is the same output.

## 5. Problem F2: option-order dependence. Methodology

### 5.1 Why it happens (precisely)

With `readout="terminator"` the logit for option *i* is read at the newline ending option *i*'s line. Causal attention means
that position saw the image, state, question and options `≤ i`, never options `> i`. Two consequences: (1) early options are
scored without their competitors, (2) each option's tokens sit at different absolute (MRoPE) positions depending on the order.
The head transformer (`head_layers=2`) is bidirectional over the read-out vectors, so it can *compare* the option summaries,
but it compares summaries that were themselves computed asymmetrically.

### 5.2 Fixes, from cheapest to most complete

| Fix | Mechanism | Removes | Cost |
|---|---|---|---|
| **B1. Block option attention on Qwen3-VL** | 4-D mask: prefix causal; every option token attends to the whole option block (all options, both directions) and the prefix; read-out unchanged | consequence (1) | port of the SmolVLM path (`vlm.py:686, 730`) to Qwen's MRoPE path; check `transformers` 5.17 Qwen3-VL accepts a 4-D float mask under SDPA; est. 2 days |
| **B2. Shared option positions** | give every option span the same starting position id (options are "parallel" in position space); MRoPE text positions are 1-D so this is a `position_ids` override | consequence (2) | 1 day; needs fine-tuning (pretrained model never saw it), which Phase A provides |
| **B3. Decision-position read-out (Imajev-style)** | one position after the option block; head maps its hidden state to K logits by attending over the K option summaries (query = decision state, keys = option read-outs) | (1) for the final score | 1–2 days; ablation arm |
| **B4. Permutation consistency loss** | two orders of the same row in one batch; `KL(p(order1) ‖ unpermute(p(order2)))`, β 0.1 | residual asymmetry | trivial in `vlm_train.py`; doubles per-row cost on 10% of rows |

**B1 + B2 together make the backbone computation order-equivariant** for the option block (same tokens, same positions, same
attention set), and the existing bidirectional head is already permutation-equivariant, so the whole read-out becomes
equivariant up to numerical noise, with **no inference cost**. This is the "permutation-equivariant candidate encoder" V6
asked for; it needs no Set-Transformer module because the head transformer already is one.

Caveat for Qwen3.5 (hybrid DeltaNet): the linear-attention layers cannot take the block mask, so only B2 + B4 + the head apply
there; residual asymmetry is expected. This is the strongest technical reason to prefer Qwen3-VL-4B if the bake-off is close.

### 5.3 Experiment P0-2 (2B, local, 3 runs × 2 h)

Arms: (a) current; (b) B1 + B2; (c) B3; all with B4. Same data / seed / steps (the diagnostic recipe).
Metrics: accuracy, **flip rate over 8 random orders**, position-bias curve (accuracy of the gold option by its position), ECE,
choice↔noul agreement, latency. Acceptance to adopt: flip rate < 1.5% and accuracy within −0.5 points of (a).
Report with paired bootstrap CIs; n = 1,660 val rows makes ±1 point resolvable.

## 6. Problem F1/F3 data: teacher quality, hard eval, abstention

### 6.1 Disagreement is information, used three ways
Eval-only hard set (`teacher_hard_eval`), soft targets when the answerer mass concentrates, and **active-learning seeds**:
families with the highest disagreement rate get more programmatic coverage (they are exactly temporal / numeric, where code can
label). No human review budget is assumed.

### 6.2 Abstention: a separate head, exported as `unknown` (chosen 2026-09-29)

Decision: **not** an extra softmax class (Imajev's design) but a factorised output, exported jointly so Jev-style clients
still get an `unknown` field.

| Output | What it answers | Trained on |
|---|---|---|
| Option head (unchanged) | P(option \| answerable), softmax over the options the user supplied | answerable rows only (option loss masked on unanswerable rows) |
| Abstain head | P(the evidence does not decide) | every row: 1 on unanswerable, 0 on answerable |
| Reason head (4) | insufficient_evidence / false_premise / not_listed / out_of_scope | unanswerable rows only |

Why not the extra class: it conflates "cannot be decided" with "unsure which option" (0.4 on `unknown` beside 0.3 / 0.3 is
ambiguous); unanswerable rows push every option logit down regardless of content, so the option ranking learns nothing from
them; one temperature must calibrate both jobs. The factorised form calibrates each part separately (a binary head is also
the natural input to conformal risk control) and gives the product distinct actions: ask for more evidence (abstain),
escalate (options close), options do not cover it (not_listed).

Implementation: the model already has an act / escalate head (`laya/vlm.py:615`, applied at `:785`) that reads the last
token after the option block through the bidirectional head transformer plus probability features (top-1, margin, entropy,
option count); it is untrained today (`train_act` off, hence the meaningless `act_probability` in JevBench outputs). The abstain
head reuses that shape (new weights), the reason head is a 4-way linear on the same features. Loss: option CE / RLCD on
answerable rows; BCE(abstain) on all rows (weight 0.5); CE(reason) on abstain rows (weight 0.2). A user-written option such
as "none of the above" or "cannot be determined" stays an ordinary option (the `none_of_above` augmentation trains it).

Export: `answers[k]["probabilities"]` = `[(1 - a) * p_1, ..., (1 - a) * p_K]` plus `"unknown": a`, and `"abstain_reason"`;
the raw `p` and `a` are also returned. Serving policy: act if `(1 - a) * max p` clears the customer's threshold; request more
evidence if `a` is high; escalate if the options are close. Thresholds fitted on the calibration set against a target risk.

Data (answerable : abstain ≈ 85 : 15):

| Reason | Source | State |
|---|---|---|
| insufficient_evidence | `vizwiz_answerable` (unanswerable), `squad_answerable`, `tydiqa_answerable` negatives; masked-evidence image pairs; generator rows with a withheld input; MuSiQue unanswerable | first three exist |
| not_listed | any choice row with the gold removed and no "none of the above" option (augmentation, exact) | derivable from all choice data |
| false_premise | teacher pipeline family; TDIUC "absurd" questions | to build |
| out_of_scope | question paired with an unrelated image / state (irrelevance controls) | to build, cheap |

Metrics: correct-abstention rate on unanswerable sets, **false-abstention rate ≤ 2%** on answerable sets (gate), reason
accuracy, risk–coverage curve, AURC, risk at 50 / 75 / 90 / 95% coverage. JevBench scoring counts only the option answer, so the
abstain head does not change benchmark accuracy; it is measured on our own panels. Effort ≈ 1 day; scheduled in round 2.

### 6.3 Counterfactual image pairs
Extend `visionjev_synthvis.py` and the invoice / refund / alert renderers to emit **(image, edited image)** pairs where exactly
one causally relevant field changes and the gold changes with it (or becomes `unknown` when the field is blanked). Target 20k
pairs; both members in the same batch with a consistency term that the two answers must differ (margin loss on the changed
field). This is our multimodal counterpart to the hard-question stage.

## 7. Problem F3: calibration and format

### 7.1 Jev-shaped calibration set
1,500 items: 3 held-out teacher domains (§4.4), 500 programmatic held-out, 300 `laya_typed` rows never trained on. Fit
per-type × per-option-count temperatures by NLL (`temperature_by_options`, already in the agent); compare with a single
temperature and with vector scaling; pick by NLL on a second held-out slice. Report NLL, Brier, ECE (15 bins), class-wise
ECE, AURC. Expected effect: removes the `laya_typed` inversion (0.10 → 0.19) and moves JevBench ECE toward ≤ 0.04
(estimate; Imajev reaches 0.026 with one temperature fitted on 150 Jev-style items).

## F.4 Documents: pixels, parsed text, or both (added 2026-09-29)

Today every document set (DocLayNet, CORD, `synth_*_doc`, RICO/ScreenQA) is **image-only**: `state_text` is empty and the
page goes in as pixels under the Qwen budget of 589,824 pixels (≈ 768 × 768), i.e. a 1,025-px DocLayNet page is downscaled
~1.8× in each direction. Small print is unreadable at that size (`doclaynet_read_small` vs `_large` is the probe). The
text/JSON versions (`synth_invoice`, WikiSQL, SWE) are separate rows, never paired with the image.

Production applications will not send a PDF as a photo: they parse it. So the training distribution should match the three
input shapes an application can send, with the same question and label across them:

| Shape | Source of the text | Share of document rows | Purpose |
|---|---|---|---|
| A. parsed text / JSON only | PDF text layer (docling, MIT), OCR for scans (PaddleOCR / Tesseract, Apache-2.0), HTML for screenshots (WebSight) | 40% | the common production case; long-context text reasoning; cheapest to serve |
| B. image + parsed text | same parser output alongside the page image; 20% of these rows carry **injected parser noise** (dropped cells, digit swaps, merged columns) with the label computed from the true document | 40% | the reconciliation case: the model must check the text against the pixels and prefer the pixels when they disagree |
| C. image only | as today | 20% | scans without a text layer, photos of documents, stamps / signatures / checkboxes / charts, robustness |

Free text layers we already hold: DocLayNet ships the PDF text cells per layout box; CORD ships ground-truth OCR lines;
PubTables-1M / FinTabNet ship cell text; WebSight ships the HTML; our synthetic renderers know every field. So shapes A and B
cost no new labelling, only a builder change (`state = {"text": ..., "layout": [...]}` or the structured record).

Resolution: raise `qwen_max_pixels` to ~1.2M for shape-C document rows only (Qwen3-VL has dynamic resolution; ~1.6k image
tokens instead of ~750; latency ≈ +40% on those rows, estimate), and keep the default for photos. With a text layer present
(A/B) the pixel budget can stay low, which is the cheaper path in production.

Arithmetic belongs in the harness, judgement in the model: for invoice / PO / statement checks the application's parser can
compute sums and differences and pass them as fields; the model's questions then become the ones a one-pass read-out is good
at (is this a duplicate, does the vendor match the PO, is the exception justified, is the parsed total consistent with the
page). Training rows of shape B with *wrong* harness-computed fields teach the model to catch harness errors instead of
trusting them.

Serving: a `/decide/document` endpoint that accepts a PDF, runs docling (CPU, tens of ms per page) and sends text + page
images to the model, so customers get the harness without building it. Text-only benchmarks (JevBench, Decision Index)
measure shape A; Image JevBench measures shape C; our own panels must report all three.

## F.5 Multi-resolution training for images and documents (added 2026-09-29)

Goal: one model that reads a receipt's small print at high resolution and a product photo at low resolution, chosen per
request, without two checkpoints. Today the pixel budget is one number per checkpoint (`qwen_max_pixels` = 589,824, applied to
the processor once at load, `laya/vlm.py:1027`); every image is resized to that ceiling at train and test time.

### Design

1. **Per-row pixel budget, processor ceiling at the maximum.** The processor keeps `max_pixels = 2.0M` (the largest budget);
   each training draw resizes the image itself to a sampled area before the processor sees it, so the processor's own
   resize is a no-op below the ceiling. Implemented in `ItemStream` / `visionjev_augment.image_ops` (which already resizes),
   not in the processor. `max_len` is set from the largest budget (`768 + max_image_tokens(2.0M)` ≈ 3.4k) so no row overflows.
2. **Budget ladder and per-dataset ranges** (Qwen3-VL tokens ≈ pixels / 1,024 after the 2×2 merge; latency grows roughly
   linearly in tokens):

   | Budget | ≈ tokens | Drawn for |
   |---|---|---|
   | 0.15M (~384²) | 150 | thumbnails: presence / count / framing / quality / photo_condition, robot frames (30% of their draws) |
   | 0.3M (~550²) | 300 | photos default (50% of photo draws) |
   | 0.6M (~768²) | 600 | photos high (20%); documents / screens low (25%) |
   | 1.2M (~1100²) | 1,200 | documents / screens default (50%); charts; UI screenshots |
   | 2.0M (~1400²) | 2,000 | documents high (25%): small print, dense tables, full A4 pages (DocLayNet native 1,025 px fits without loss) |

   Each dataset declares a range in its manifest (`res: photo | doc | screen | chart`); the sampler draws a budget per draw
   from the range with the shares above. Images smaller than the drawn budget are never upscaled.
3. **Same row at two resolutions = a consistency pair.** For 10% of document / screen draws, the same example is emitted
   twice in one batch at a low and a high budget with the same label; a consistency term (KL between the two predictions,
   weight 0.1) plus the label makes the model's answer stable where the low resolution suffices and lets it be *uncertain*
   at low resolution where it does not (the label loss is down-weighted 0.5 on the low copy of `doclaynet_read_small`-type
   rows, so the model is not forced to hallucinate unreadable text).
4. **Harness pairing (F.4):** shape-B rows (image + parsed text) are drawn at the *low* budgets by default. The text layer
   carries the content; pixels carry layout and visual cues. Shape-C rows (image only) draw from the full document range.
5. **SmolVLM path:** the same ladder maps onto tiling (`split_edge`, `max_tiles`), already supported (`default_max_len`).

### Inference: resolution routing

- **Default per request type:** documents / screenshots 1.2M, photos 0.3M; the API accepts `max_pixels` per image and the
  document endpoint (F.4) sets it from page size and text density (pages with a text layer → 0.6M; scans → 1.2M).
- **Resolution cascade (cheaper than a model cascade):** if `max p < τ_res` on an image question at the default budget,
  re-run the same model at the next budget up (one more pass, ~2× image tokens) before deferring to the 30B. Router
  features as in §4.8 plus the current budget. Expected: most small-text failures resolve at 1.2–2.0M without touching the

### Evaluation

- Accuracy and ECE **per budget** on: `doclaynet_read_small` / `_large`, CORD totals, `synth_*_doc`, chart_qa, rico_screenqa,
  and the photo panels (oi_*, aokvqa) — a resolution–accuracy curve per set; the photo sets must be flat (no gain from
  pixels = no wasted tokens), the document sets must rise and saturate by 1.2–2.0M.
- Latency per budget (`visionjev_latency` with a `--max-pixels` sweep) to price the routing thresholds.
- Gate: at each set's default budget, accuracy ≥ the single-budget checkpoint; small-text sets +10 points at 2.0M
  (target, estimate); photo latency −40% at 0.3M vs today's 0.59M.

### Cost

Training cost per image row scales with tokens; with the shares above the *average* image row costs about the same as
today (photos get cheaper, documents dearer). No new data: it is a sampler and a processor-ceiling change (est. 1–2 days),
plus the consistency pair in the trainer (half a day). It goes into the fast track on days 2–3 alongside the text/image budget
split (§4.1), because both touch the same `max_len` accounting.
