# VisionJev v6

## A permutation-invariant, calibrated, selectively-routed multimodal decision model

**Status:** Proposed research design
**Goal:** Build a multimodal typed-decision model that is fast on easy cases, strong on multi-step reasoning, robust to option ordering, and able to abstain or escalate when evidence is insufficient.

---

# 1. Executive Summary

VisionJev should not simply reproduce Imajev's architecture.

Imajev demonstrates that a relatively small VLM can become a strong typed-decision model through carefully staged supervised training. Its most important empirical findings are highly relevant to us:

* Broad decision fine-tuning can substantially damage the backbone's existing reasoning ability.
* A small amount of targeted hard-reasoning data can recover much of that loss.
* A single decision position after the entire option block avoids the structural option-order bias present in our current per-option readout.
* Explicit `unknown` examples improve abstention behavior.
* Exact programmatically generated problems are particularly valuable for numerical and temporal reasoning.
* Weight averaging can trade off specialized capabilities successfully.
* Serving optimizations such as LoRA merging, CUDA graphs and prefix caching matter because decision models are intended to be extremely cheap and fast.

However, several conclusions in the Imajev analysis are hypotheses rather than established causal findings. In particular, we should not assume that its teacher-agreement filtering, rationale loss, global temperature, arbitrary option-code scheme, or one-pass reasoning constraint are optimal.

The proposed VisionJev v6 therefore has five design principles:

> **1. Preserve the pretrained VLM before adding decision specialization.**

> **2. Represent candidate options as an unordered set rather than relying on token-position tricks.**

> **3. Train hard reasoning with verified computational supervision whenever possible.**

> **4. Treat uncertainty and abstention as a selective-prediction problem, not merely an `unknown` class.**

> **5. Use adaptive inference: easy cases get one pass; uncertain cases receive additional reasoning or verification.**

# 2. What We Are Actually Building

The model receives:

```text
IMAGE(S)
+
APPLICATION STATE
+
QUESTION
+
BOUNDED SET OF CANDIDATE ANSWERS
```

and returns:

```text
P(y = option_1)
P(y = option_2)
...
P(y = option_K)
P(abstain)
```

The important difference from a conventional VLM is that the model does **not generate a textual answer**.

The application should therefore be able to write:

```python
decision = model(state, image, question, options)

if decision.confidence >= threshold:
    execute(decision.option)
else:
    escalate()
```

The model is a **decision primitive**, not a chatbot.

This matches the fundamental motivation behind Jev-style systems: bounded state + bounded rubric → typed probabilities rather than free-form prose.

---

# 3. Problems With the Current VisionJev Design

Our current system reads each option at the token terminating that option's text. Because the backbone is causal, the representation for option `i` cannot see options appearing later in the prompt.

The current report measured approximately **5.8–7.1% answer flips under option reordering**.

Randomized training and inference-time rotations mitigate this, but they do not remove the underlying architectural asymmetry.

This should be treated as a first-class architecture problem.

## Desired property

For:

```text
[A, B, C, D]
```

and:

```text
[D, A, C, B]
```

the model should produce the same probabilities associated with each semantic option, modulo the permutation.

This is naturally an **unordered-set prediction problem**.

Set Transformer provides an established framework for permutation-invariant/equivariant processing of set elements while allowing the elements to interact with one another.

# 5. Candidate Representation: Replace Arbitrary Code Tokens

Imajev currently binds each candidate to one of 255 single-token codes and reads all options from a single decision position. This is a clever solution to causal option visibility and removes much of the position-order problem.

We should reproduce the **important property**, not necessarily the exact mechanism.

## Proposed candidate module

Let:

```text
h_c = global/context representation
h_i = representation of candidate i
```

Construct:

```text
z_i = CandidateEncoder(h_c, h_i, {h_1,...,h_K})
```

and:

```text
logit_i = MLP(z_i)
```

The candidate encoder should use permutation-equivariant attention over candidates.

For example:

```text
candidate embeddings
       ↓
self-attention over candidate set
       ↓
cross-attention with global state
       ↓
candidate-specific scores
```

This has three advantages:

1. Every option can see every other option.
2. Reordering candidates does not change the underlying computation.
3. There is no arbitrary 255-token vocabulary ceiling.

Set Transformer is directly relevant here because it was designed specifically to model sets where ordering should not affect the function being learned.

### P0 experiment

Compare:

```text
A. Current per-option terminator readout
B. Imajev-style single decision position
C. permutation-equivariant candidate module
```

Measure:

```text
accuracy
option-order flip rate
calibration
latency
```

Do not assume C wins. **Measure it.**

# 6. Separate "Choosing an Option" From "Knowing Whether to Act"

A major architectural mistake would be to treat `unknown` as simply another classification label.

The current Imajev model intentionally includes an `unknown` code for insufficient evidence, false premises, mismatched reference images, and answers outside the candidate set.

This is useful, but these conditions represent different phenomena.

We should separate:

### Task 1 — Which option is correct?

```text
P(y = i)
```

### Task 2 — Is the evidence sufficient to make a decision?

```text
P(abstain | x)
```

Then the serving system decides:

```text
                     model confidence
                           │
             ┌─────────────┴─────────────┐
             │                           │
         sufficiently                 uncertain
           reliable                       │
             │                            ▼
             ▼                       escalate
           execute
```

This turns abstention into a **selective prediction** problem.

The appropriate evaluation is therefore not only accuracy on an `unknown` class. We should measure the complete **risk–coverage curve** and AURC, which is a standard metric for selective prediction.

---

# 7. Abstention Taxonomy

Instead of training everything as one generic unknown label, annotate the reason where possible:

```text
UNKNOWN:
    insufficient_evidence
    false_premise
    missing_option
    mismatched_reference
    out_of_scope
    ambiguous
```

We do not necessarily need six separate output probabilities.

A practical output can remain:

```json
{
  "option_probabilities": {...},
  "abstain_probability": 0.81,
  "abstain_reason": "insufficient_evidence"
}
```

This allows the application to distinguish:

```text
"I cannot tell."
```

from:

```text
"None of these options applies."
```

from:

```text
"This input is outside my supported domain."
```

# 8. The Most Important Training Principle: Protect the Base Model

Imajev's most striking result is the Stage-1 collapse:

```text
9B base through decision readout: 64.9% hard
                    ↓
after Stage 1:      42.3%
                    ↓
after Stage 3:      67.6%
```

The authors interpret this as a reasoning collapse and show that targeted hard examples recover much of it.

Catastrophic forgetting during continual fine-tuning is a documented phenomenon in LLMs and has been observed across reasoning, domain knowledge and reading comprehension.

However, we should not assume every drop is literal destruction of reasoning circuitry. It may partly be a **representation/readout mismatch** caused by learning a new decision objective.

Therefore:

## First experiment

Evaluate three paths:

```text
Base VLM
   │
   ├── ordinary LM evaluation
   │
   └── decision readout evaluation

Fine-tuned VLM
   │
   └── decision readout evaluation
```

This tells us whether the degradation occurs in:

```text
backbone capability
```

or:

```text
mapping backbone representations → decision logits
```

That distinction should determine the training strategy.

---

# 9. Proposed Anti-Forgetting Objective

For the broad training stage:

```text
L = L_decision + λ KL(p_base || p_student)
```

where:

```text
p_base    = frozen base model distribution
p_student = current decision distribution
```

A practical initial sweep:

```text
λ ∈ {0, 0.1, 0.3, 0.5}
```

This is conceptually related to Learning without Forgetting, which preserves existing behavior while learning new tasks.

For parameter-efficient fine-tuning, we should additionally test stronger constraints on the adapter updates.

Fine-tuning instability and forgetting have been extensively studied, including methods such as pretrained-weight regularization, layer-wise learning rates and Mixout-style regularization.

Purpose:

```text
teach the model:
    decision format
    candidate grounding
    multimodal state interpretation
    schema

```

Use broad, high-quality data:

```text

VQA

OCR

contradictions
intent classification
routing
moderation
structured extraction
```

Do **not** rely exclusively on short pattern-classification datasets.

Our current broad mixture contains approximately one million rows over roughly one hundred datasets and is dominated by short decision patterns. The internal report already shows that this distribution can be associated with reasoning degradation.

### Loss

```text
L_A =
    CE(decision)
  + λ KL(base || student)
  + β consistency(permutation)
  + γ abstention_loss
```

Suggested starting point:

```text
LR:        2e-5 – 5e-5
LoRA:      moderate rank
KL weight: 0.1 – 0.5
```

Run multiple seeds.

# 12. Phase B — Verified Hard Reasoning

This should be the most important new training stage.

Imajev's hard-data stage is compelling: approximately 14k teacher-agreed hard questions increased the 9B hard score from 42.3% to 67.6%.

But its teacher-agreement filter has an important limitation:

```text
KEEP only if teachers agree
```

This preferentially keeps cases where the teachers already agree and can remove precisely the difficult cases we care about.

The PDF itself reports survivor bias, particularly for numerical items.

## Better approach

Split generated data into four pools:

```text
UNANIMOUS
    ↓
high-confidence training data

2/3 AGREEMENT
    ↓
verification / secondary labeling

DISAGREEMENT
    ↓
hard-case / active-learning pool

PROGRAMMATIC
    ↓
exact ground truth
```

Do not throw away all disagreement.

# 13. Exact-Answer Generators

For reasoning that can be verified by code, use executable ground truth instead of teacher consensus.

Target families:

```text
temporal arithmetic
business days
time zones
DST
unit conversion
rounding
probability
Bayes
expected value
financial reconciliation
tax
discounts
FX
multi-hop table reasoning
rule precedence
scheduling
```

Generate **specific mistake distractors**.

Example:

```text
Correct:
2026-03-10 17:00 EST

Distractor:
2026-03-10 17:00 UTC       # timezone error

Distractor:
2026-03-11 17:00 EST       # date arithmetic error

Distractor:
2026-03-09 17:00 EST       # sign/order error
```

The important principle is:

> The wrong option should correspond to a recognizable reasoning failure.

Imajev uses this idea in its programmatic generators and independently recomputes answers with code.

We should expand it substantially.

Target:

```text
20k–50k exact reasoning examples
```

with at least:

```text
50% text / JSON
25% visual documents / screenshots
25% image + structured-state reasoning
```

# 14. Multimodal Hard Reasoning

This is where VisionJev should differentiate itself from text-only Jev models.

Examples:

### Image + record contradiction

```text
record:
product_color = "red"

image:
product is visibly blue

question:
Does the evidence support the record?
```

### Image + document + policy

```text
image of invoice
+
purchase-order record
+
company policy

question:
Which candidate action is allowed?
```

### Evidence sufficiency

```text
image is partially occluded

question:
Is there enough visual evidence to approve the item?
```

### Counterfactual visual pairs

Create:

```text
image A → answer A
image B → answer B
```

where B differs by exactly one causally relevant property.

These contrastive examples are particularly valuable because they teach the model:

> **the decision depends on evidence, not merely on the question wording.**

The current report already uses masked-evidence and edited-copy examples; v6 should make this a much larger training family.

# 15. Teacher Distillation

Use teacher models for cases where there is no cheap exact verifier:

```text
writer
   ↓
problem
   ↓
2–3 independent answerers
   ↓
distribution + rationale
```

But change the acceptance policy.

### Unanimous agreement

Use as high-confidence soft-target data.

### Disagreement

Do not immediately discard.

Instead:

```text
disagreement
     ↓
stronger verifier
     ↓
human review OR exact solver
```

The teacher itself should also provide:

```text
P(A)
P(B)
P(C)
P(unknown)
```

rather than only:

```text
A
```

Soft targets preserve information about near-miss alternatives and uncertainty, which is the core advantage of knowledge distillation. The original distillation literature showed that the full probability distribution carries useful “dark knowledge.”

The Imajev Stage-4 soft-target stage follows this principle.

---

# 16. Rationale Supervision — Use Carefully

I would **not make rationale loss a core dependency**.

Imajev adds an auxiliary rationale language-model loss but explicitly notes that it has not published an isolated ablation showing the contribution of this term.

Instead:

### For exact tasks

Use verified intermediate computations.

```text
question
→ program
→ intermediate values
→ final answer
```

### For visual tasks

Use executable visual programs or structured evidence traces where possible.

Visual Program Distillation is directly relevant: it demonstrated that executable intermediate programs can provide useful supervision for multimodal reasoning, rather than relying exclusively on free-form textual rationales.

### For non-verifiable reasoning

Use teacher rationales as an auxiliary objective, but ablate:

```text
β = 0
β = 0.1
β = 0.3
β = 0.5
```

The model should still work if rationale loss provides zero benefit.

# 17. Phase C — Reasoning Delta

After broad training, perform a **short hard-data delta** rather than another large general fine-tune.

```text
Broad model
     │
     ▼
20–50k hard examples
     │
     ▼
low LR / few hundred steps
     │
     ▼
reasoning-specialized model
```

Use:

```text
LR: 2e-5 – 3e-5
steps: 100–500
10–20% replay from broad data
```

The purpose is not to teach the entire model new knowledge.

It is to teach the decision head and surrounding representations to **access capabilities already present in the pretrained model**.

Imajev's 80–300-step recovery is strong evidence that this is worth testing.

# 18. Phase D — Adaptive Reasoning

This is the major architectural departure from Imajev.

Do not force every example to be solved in one pass.

## Fast path

```text
image/state/question
       ↓
decision model
       ↓
high confidence?
       ↓ YES
return
```

## Hard path

```text
low confidence
     ↓
latent refinement / second reasoning pass
     ↓
updated representation
     ↓
decision head
```

Possible implementations:

### Option 1 — Second VLM pass

Simple and reliable.

### Option 2 — Latent iterative refinement

```text
h_0
 ↓
reasoning block
 ↓
h_1
 ↓
reasoning block
 ↓
h_2
 ↓
decision
```

Latent reasoning research such as Coconut demonstrates the potential of feeding continuous hidden representations back into the model rather than forcing every intermediate state through natural-language tokens.

However, this should remain experimental: later work has raised concerns that latent-token reasoning can exploit shortcuts rather than faithfully encode reasoning.

Therefore the correct position is:

> **Test latent refinement; do not assume it is genuine reasoning.**

# 19. Verification Cascade

A potentially stronger product architecture is:

```text
                 Request
                    │
                    ▼
              2B Decision VLM
                    │
             confidence score
              /           \
          high             low
           │                │
           ▼                ▼
        return         larger verifier
                           │
                      confident?
                      /       \
                    yes        no
                    │           │
                  return      human/
                             fallback
```

This can give us:

```text
~1-pass latency for easy cases
+
higher reliability on hard cases
```

rather than sacrificing all requests to the cost of a large reasoning model.

Research on test-time scaling shows that allocating additional inference compute can materially improve reasoning on difficult problems; importantly, modern work emphasizes that the **inference protocol itself must be reported**, because “test-time scaling” encompasses multiple distinct algorithms and compute regimes.

# 20. Calibration

Temperature scaling should remain the baseline.

But it should not be the entire calibration strategy.

Imajev uses one temperature fitted on 150 Jev-style items.

VisionJev should compare:

```text
temperature scaling
vector scaling
Dirichlet calibration
```

Dirichlet calibration is a particularly relevant multiclass alternative because it learns a richer mapping than a single global temperature and has been shown to improve several calibration measures.

Fit calibration on data that is:

```text
NOT in training
NOT used for model selection
NOT generated from the same exact templates
```

And stratify by:

```text
decision type
option count
image present/not present
difficulty
domain
```

Do not use a single number such as ECE as the only reliability criterion.

Report:

```text
NLL
Brier score
ECE
classwise ECE
AURC
risk @ 50% coverage
risk @ 75%
risk @ 90%
risk @ 95%
false-abstention rate
```

# 21. Add Conformal / Risk-Controlled Abstention

This is a major opportunity.

Instead of:

```text
if max_probability > 0.8:
    act
```

use a calibrated selective policy.

The desired product contract becomes:

> At a specified operating coverage, keep decision risk below a target on the calibration distribution, subject to the assumptions of the method.

Conformal Risk Control extends conformal prediction to control expected values of monotone losses and provides a formal framework for choosing thresholds under finite samples.

Recent work specifically examining structured LLM outputs also shows that heuristic abstention can miss desired risk targets, while conformal approaches can improve risk control—but that certification becomes impossible when base error is already too high.

Therefore v6 should have:

```text
model probability
      ↓
calibrator
      ↓
risk controller
      ↓
ACT / ABSTAIN / ESCALATE
```

The model should not be allowed to claim reliability simply because its softmax probabilities look reasonable.

---

# 22. Model Uncertainty

As a second research axis, test a small ensemble:

```text
model seed 1
model seed 2
model seed 3
       ↓
probability aggregation
```

Deep ensembles are a well-established method for predictive uncertainty and can improve calibration and uncertainty under distribution shift.

We should **not** run an ensemble on every request if latency/cost is the product constraint.

Instead, use it to:

1. validate whether disagreement is predictive of failure;
2. train/calibrate the cheap uncertainty model;
3. potentially activate the ensemble only on borderline cases.

---

# 23. Option Permutation Training

Every training example should see random option ordering.

However, the architecture should already be permutation-equivariant.

Therefore:

```text
training permutation
+
architectural permutation invariance
```

should replace:

```text
training permutation
+
inference-time averaging over rotations
```

Imajev reports that four rotations can improve hard accuracy, but at approximately three times the latency, while its official board run used one rotation.

Use rotations as an **evaluation and optional production fallback**, not the primary method of fixing order bias.

---

# 24. Vision Encoder Strategy

Do not automatically freeze the vision encoder.

Imajev freezes its vision tower, which is an efficient and defensible baseline.

But VisionJev has a more demanding multimodal task:

```text
image
+
state
+
policy
+
candidate comparison
```

rather than simply recognizing an image.

Therefore run:

```text
A. frozen vision tower
B. train projector only
C. LoRA late vision layers
D. LoRA projector + late vision layers
E. selective/full visual adaptation
```

Evaluate separately on:

```text
image-only
image + state
image contradiction
OCR
document understanding
charts
UI screenshots
visual counterfactuals
```

The goal is to determine whether the visual encoder itself needs task-specific adaptation.

# 26. Training Loss

A practical starting objective:

```text
L_total =

      L_decision
    + λ1 L_KL(base, student)
    + λ2 L_permutation
    + λ3 L_abstention
    + λ4 L_reasoning
```

where:

### Decision loss

```text
CrossEntropy(student distribution, target distribution)
```

### Base-preservation loss

```text
KL(p_base || p_student)
```

### Permutation consistency

For two permutations of the same candidate set:

```text
KL(
   p_student(original),
   unpermute(p_student(permuted))
)
```

### Abstention loss

Separate supervision for:

```text
answerable
insufficient evidence
false premise
missing candidate
```

### Reasoning loss

Prefer:

```text
verified computation
```

over free-form rationale wherever possible.

# 29. Statistical Evaluation

Do not report a single benchmark number from one run.

For each major experiment:

```text
3–5 random seeds
paired evaluation
95% confidence intervals
bootstrap over examples
```

For small benchmarks such as the 111-item hard tier, even seemingly meaningful percentage-point differences can correspond to only a handful of examples.

Therefore, for every claimed improvement:

```text
Δ accuracy
95% CI
N
paired significance test
```

The internal report's 72.1% vs 67.6% style comparisons should be treated as engineering evidence, not automatically as statistically decisive superiority.

# 30. Release Gates

A new model should not ship merely because JevBench improves.

Candidate model must satisfy:

```text
JevBench:
    improve or remain within tolerance

General reasoning:
    no meaningful regression

Multimodal:
    no regression

Order robustness:
    flip rate < 1%

Calibration:
    NLL/Brier/ECE within target

Abstention:
    risk decreases monotonically with lower coverage

OOD:
    uncertainty increases appropriately

Vision:
    no regression

Latency:
    within budget

Cost:
    within budget
```

The exact thresholds should be defined before evaluating the candidate.

The current report already advocates coded release gates and held-out photo sources; this should become an automated CI/CD process rather than a manual checklist.

# 32. What We Should Copy From Imajev

Keep:

### 1. Hard-question curriculum

Strong empirical evidence supports it.

### 2. Programmatic exact-answer generation

Especially for numerical/temporal reasoning.

### 3. Explicit abstention

This is central to reliable deployment.

### 4. Anti-forgetting regularization

Supported by the broader continual-learning literature.

### 5. Fast serving

Merged LoRA, CUDA graphs, caching and fixed-shape inference are exactly the kinds of optimizations a decision API needs.

---

# 33. What We Should Not Copy Blindly

### 1. Arbitrary 255 code tokens

Use a permutation-equivariant candidate representation instead.

### 2. Teacher unanimity as the universal quality filter

Use disagreement as information.

### 3. One global temperature

Benchmark alternatives such as Dirichlet calibration.

### 4. `unknown` as one monolithic class

Separate decision confidence from abstention and characterize the reason.

### 5. Rationale loss as an assumed win

Run a clean ablation.

### 6. Four inference rotations as the primary order-bias solution

Fix the architecture instead.

### 7. One-pass reasoning as an absolute requirement

Use adaptive compute for difficult cases.

### 8. JevBench as the only definition of progress

Build a much larger multimodal, human-audited benchmark.

---

# 34. The Target Product Architecture

The final system should look like:

```text
                    USER / APPLICATION
                           │
                           ▼
                IMAGE + STATE + QUESTION
                           │
                           ▼
                 FAST DECISION VLM
                           │
               permutation-invariant
                    candidate head
                           │
                           ▼
                  calibrated scores
                           │
                           ▼
                   selective policy
                 ┌─────────┼─────────┐
                 │         │         │
                 ▼         ▼         ▼
                ACT      REFINE    ABSTAIN
                           │
                           ▼
                 larger verifier /
                 additional reasoning
                           │
                           ▼
                    final decision
```

The key product property is:

> **The model does not need to be maximally intelligent on every request. It needs to know when a cheap decision is reliable and when additional computation is justified.**

That is a substantially more useful objective than maximizing raw one-pass benchmark accuracy.

---

# 35. Research Hypotheses

The v6 project should explicitly test these hypotheses:

### H1

Permutation-equivariant candidate encoding reduces option-order sensitivity more effectively than inference-time rotations.

### H2

A KL-to-base objective reduces capability loss during broad decision fine-tuning.

### H3

Hard reasoning data produces larger gains per training example than adding more broad classification data.

### H4

Programmatically verified reasoning produces more reliable gains on numerical/temporal tasks than teacher-only labels.

### H5

Teacher disagreement is useful training information rather than merely low-quality data.

### H6

Explicit evidence-sufficiency training improves selective prediction.

### H7

A second inference pass on uncertain examples yields a better accuracy/latency tradeoff than making the entire model larger.

### H8

Multimodal hard reasoning and counterfactual image pairs improve genuine image-grounded decision making more than generic VQA volume.

---

# 36. Bottom Line

The goal of VisionJev v6 should **not** be:

> “Reproduce Imajev's 86%.”

The goal should be:

> **Build a decision model whose accuracy, probability estimates, abstention behavior and multimodal grounding remain reliable when the input distribution changes.**

Imajev gives us an excellent empirical starting point. Its results strongly suggest that **training-data composition and a short hard-reasoning stage matter enormously**, and that decision models can be trained cheaply.

But the next step should be architecturally more ambitious:

```text
Imajev:
    image/state
       ↓
    one-pass decision
       ↓
    probability

VisionJev v6:
    image/state
       ↓
    permutation-invariant decision
       ↓
    calibrated uncertainty
       ↓
    ┌───────────────┐
    │ reliable?     │
    └───────┬───────┘
        yes │ no
            │
       execute / refine
                 ↓
            verify / abstain
```

That gives us a model that is not merely **good at choosing an answer**, but is designed around the more difficult systems question:

> **When should an AI system be trusted to make a decision automatically?**
