## 3. Abstention (chosen design; was V6.1 §6.2)

Factorised output, exported jointly as `unknown`:

| Output | Answers | Trained on |
|---|---|---|
| Option head | P(option \| answerable) over the user's options | answerable rows (option loss masked on unanswerable rows) |
| Abstain head | P(the evidence does not decide) | all rows (BCE, weight 0.5) |
| Reason head (4) | insufficient_evidence / false_premise / not_listed / out_of_scope | unanswerable rows (CE, weight 0.2) |

Reuses the act-head input (last token after the option block through the bidirectional head transformer + top-1, margin,
entropy, option count; `laya/vlm.py:615, 785`). Export `[(1-a)p_1 … (1-a)p_K]` + `"unknown": a` + `"abstain_reason"`.
Data at answerable : abstain ≈ 85 : 15 (VizWiz / SQuAD 2 / TyDi unanswerables; "gold removed" rows for not_listed; withheld-
input generators; masked-evidence image pairs; teacher false-premise items; irrelevance controls). Gate: false abstention
≤ 2%. Metrics: correct-abstention rate, AURC, risk at 50 / 75 / 90 / 95% coverage.

## 4. Agentic trajectory training (new)

### 4.1 Why

Agents make many small decisions per task: which tool, which file, which UI element, whether to stop, whether the run is
going well, which of N candidate solutions to keep. These are system-one decisions over a bounded candidate set, i.e. our
product, and a market that frontier-model verifiers serve slowly. Contrastive Language Models (Stanford / NVIDIA, Sep 2026)
show that step-level state–action training transfers to best-of-N verification (DeepSWE 81.6%, Terminal-Bench 2.1 87.6% as a
selector over frontier-model samples). Our cross-encoder reads the options against the state (CLM scores 38.5% on JevBench
standard where our 4B scores 95.8%) and can see screenshots, which CLM cannot yet; we already beat the 30B on Mind2Web
operation zero-shot (4B 48.9% vs 31.3%).

### 4.2 How CLM does it (for reference; github.com/Contrastive-LM/CLM, Apache-2.0, read 2026-09-29)

- Every step of every trajectory is one (state, action) pair: state = chat history up to step t (chat template, tail
  truncation to ~8k tokens), action = the step taken.
- Frozen Qwen3-8B + two small projection heads; bidirectional in-batch InfoNCE; batches blocked by task so negatives are
  other steps of the same task (hard); duplicate (task, step) pairs masked out.
- **The pass / fail reward is not in the loss**; it is only used for task-disjoint folds and evaluation.
- Verifier: step score = cosine(state, action); trajectory score = mean of the final K steps; best-of-N picks the maximum;
  reported against random and oracle with exact tie handling (`evaluation/bon_eval.py`).

### 4.3 Our four task types (one trajectory dataset → four typed decisions)

| Task | Question type | Label | Hard negatives / notes |
|---|---|---|---|
| `agent_next_action` | choice (4–8) "Which action should the agent take next?" | the action taken in a **successful** run | actions from other steps of the same task; the same step in other runs of the task; mutated calls (wrong file, argument, element, flag) — mistake distractors as in the generators |
| `agent_step_progress` | score (0–4) or noul "Did this step move the task forward?" | derived from the run: steps later reverted, repeated or followed by the same error = no progress; steps on the path to a passing final state = progress | exact where the environment logs it (tests, file diffs, page state) |
| `agent_outcome` | noul "Will this run succeed?" at step t (also a `value` target) | final pass / fail | trains the existing value head (`value_head`, BCE on a [0, 1] outcome) as a calibrated early-stop / escalate signal |
| `agent_verify_pair` | choice (2) "Which final patch / state solves the task?" | tests pass / fail | a pass and a fail from the same task; generalises `swe_patch_match`; the direct best-of-N use case |

Differences from CLM, deliberate:
- Next-action labels come from successful runs only (behaviour cloning of failures teaches failures); CLM trains on all steps.
- Outcome and progress use the reward, so the model outputs a calibrated success probability, not only an alignment score.
- Screenshots are first-class state for computer-use trajectories (current observation image + action history text).
- For very large candidate sets (1,000 tools, a full DOM) a cheap retrieval shortlist picks the top 10–20 (CLM-style cached
  embeddings or BM25), then the cross-encoder decides (§5.1).

### 4.4 Construction details

- **State rendering:** task instruction + last N steps (action, observation summary, errors) + current observation; the
  middle is cut first so the instruction and the recent steps survive; budget 8,192 tokens for this domain (text) or 4,096 +
  image tokens (GUI). Tool outputs longer than 600 tokens are cut head + tail.
- **Splits:** task-disjoint (15% of tasks val only), stratified by candidate count and pass rate as CLM does, and disjoint by
  repository for code tasks (as the SWE family already is).
- **Balance:** at most 8 next-action rows per trajectory (early / middle / late steps), outcome rows at 3 positions per run,
  verifier pairs capped per task; pass : fail ≈ 1 : 1 for outcome and verifier.
- **Loss:** option CE / RLCD for choice and score tasks as everywhere; `agent_outcome` also trains the value head (BCE,
  `w_value` 0.5) so the product can read P(success) directly.
- **Mix:** agentic domain 10–15% of Phase B2 draws; ≥ 35% replay in any agent-focused delta (CLM: 40% replay kept 69.0 → 68.5
  on their held-out set; without replay 56.2).

### 4.6 Evaluation

- Next-action accuracy and calibration on held-out tasks; outcome AUROC and ECE; progress score MAE.
- **Best-of-N selection rate** vs random and oracle on held-out tasks, with the exact expectation and tie handling of
  CLM's `bon_eval.py`, so numbers compare directly.
- Zero-shot: Mind2Web element / operation (already in our suite), AndroidControl held-out.
- Gates: no regression > 1 point on the round-1 suite; JevBench within tolerance.

### 4.7 Effort

Builder + licence review ≈ 2–3 days (CPU); training rides in Phase B2 (no separate pod); verifier-pair and outcome tasks
first (exact labels, clearest product value: a cheap, calibrated judge for agent runs), next-action and progress second.

## 5. Lessons taken from Contrastive Language Models

1. **Retrieve, then decide:** a cached bi-encoder shortlists from thousands of options; our model makes the calibrated call
   among the top 10–20. Lifts the option-count limit without putting 1,000 options in context.
2. **Hard negatives after broad training** (their 69.2% two-stage vs 62.4% from the start) supports Phase A → Phase B and
   the mistake-distractor generators.
3. **Replay 35–40%** in every delta (their 40% kept 69.0 → 68.5; without, 56.2). Our ~22% lost 4 original-tier points.
4. **Frozen-backbone head sweeps** on precomputed hidden states for cheap architecture experiments (read-out variants,
   abstain head) in the autoresearch loop.
5. **Do not copy:** closed-model hard negatives (their mid-training data comes from Gemini) — our pipeline stays on
   open-weight teachers and computed labels.

## 6. Model tiers

| Tier | Model | Role | Evidence |
|---|---|---|---|
| Product | 4B (Qwen3-VL-4B) | default for all traffic | equals the 30B except knowledge / hard tier; 6× faster; best calibration |
| Premium / teacher | 8B (Qwen3-VL-8B, to measure, §2 #7) | escalations, knowledge-heavy tasks, labeller for the 4B | Imajev: 9B ≈ 4B after training on decisions, +4.7 MMLU; our 30B: +7.8 MMLU, +7.2 hard over the 4B |
| Offline only | 30B (Qwen3-VL-30B-A3B) | data labelling if the 8B falls short | cost axis penalised (≈ 26 at serial GPU cost) |

Cascade: 4B answers when `(1 - a) · max p ≥ τ`; otherwise 8B; otherwise escalate to a human. Router refit on the new tiers
(target ≥ 85% of oracle deferral).
